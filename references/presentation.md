# 公开面板、输出编排与沉浸媒体

## 【卷玖 · 灵视之镜】视觉与面板系统

### 一、公开面板模型

状态面板是一份公开状态视图。权威数据来自 state.yaml，任何渲染器都只能读取下列公开字段：

- 名字、公开身份、当前地点
- 当前主线、当下行动
- 灵性当前值／上限、理智、污染、金钱
- 身体状态、精神状态、公开状态效果
- 序列、途径、扮演度
- 最多 6 项关键随身物品
- 公开同行及其简短状态

禁止进入面板的内容：隐藏关系分、未发现 NPC 状态、幕后世界时钟、引擎真相、未公开骰点、作弊监察内部记录、角色尚未验证的补完知识。

开局锁定的视觉变量：

- 主色：#6d1f2e（雾都酒红）
- 深色：#3a0d16（暗红黑）
- 辅色：#9a6b1f（旧金）
- 底色：#f8f2ec（羊皮纸）
- 正文：#292421（墨色）
- 雾色：#a7aaa5（冷灰）
- 面板标题：状态
- 身份标签：[角色卡身份 · 当前身份]
- 主属性名：灵性（视觉符号可使用 ☾；上限随序列变化）
- 状态枚举：健康／轻伤／重伤／濒死／失控倾向／灵性枯竭
- 精神状态枚举：清醒／紧张／焦虑／恍惚／疯狂
- 提示板块：眼下可做的事／人物往来／命运线索
- 默认物品：数枚便士、一份旧报纸

所有输出界面共享唯一 public_panel_model。先生成并校验公开模型，再由当前 Agent 环境选择可用的表现形式；禁止根据输出渠道重新推断游戏状态。

### 二、触发词

- 「状态」→ 读取当前战役的 state.yaml，使用已确认可用的 panel_renderer 输出状态面板。
- 「提示」→ 使用同一公开模型输出提示面板。
- 「面板模式」→ 显示当前模式和可选模式，不推进游戏时间。
- 「面板模式视觉」→ 自动选择 HTML 截图或 SVG 截图。
- 「面板模式 HTML」→ 生成自包含 HTML，再由当前环境截图为 PNG、JPEG 或 WebP。
- 「面板模式 SVG」→ 生成自包含 SVG，再由当前环境光栅化为 PNG、JPEG 或 WebP。
- 「面板模式富文本」→ 使用平台原生富文本。
- 「降级面板」→ 使用极简文字版。
- 「恢复面板」→ 依次重试视觉快照、平台富文本与纯文字中高于当前模式且适配环境的第一个模式。
- 「插图设置」→ 显示当前插图偏好。
- 「开启插图」→ 关键场景核心信息输出后询问是否生成插图。
- 「关闭插图」→ 不再询问场景插图；不影响状态面板。
- 「角色卡」→ 输出公开角色资料（属性、技能、优势、弱点）。
- 「审计」→ 输出上一项判定的完整可公开计算过程。
- 「纠错」→ 暂停推进，核对正典、算术或状态矛盾。
- 「规则」→ 解释相关规则，不推进游戏时间。
- 「目标」→ 显示当前命运志向、完成条件与状态；尚未选择时提供 4 个背景相关选项 +「自由填写」。
- 「节奏」→ 显示紧凑／标准／长篇的当前档位、累计有意义场景与章节；允许切换，不推进游戏时间。
- 「内容设置」→ 显示恐怖、血腥、恋爱、原著剧透和硬性避雷项；允许调整，不推进游戏时间。剧透设置只影响明确的元讨论，不进入角色知识。
- 「暂停」→ 停止剧情推进；「退休」→ 进入结局确认。

角色命名完成、首轮结束、属性或状态重大变化、重要剧情推进、章节小结后，必须自动输出状态面板。重要剧情推进时，主线、当下与状态必须为最新值。

### 三、渲染与输出选择

渲染器优先级：

1. HTML 视觉快照 html_snapshot
2. SVG 视觉快照 svg_snapshot
3. 平台富文本 platform_rich_text
4. 极简文字 text

视觉快照的交付格式由当前 Agent 环境决定：

- 能直接显示本地图片：发送 PNG、JPEG 或 WebP；确认兼容时也可以显示 SVG。
- 能打开网页或截图：使用自包含 HTML，再发送截图和精简状态摘要。
- 不能显示媒体：使用富文本；再失败才用纯文字。

玩家明确指定的模式优先于自动选择。指定模式失败后恢复最近一次成功模式。渲染器只影响表现层，不得改变字段、数值、剧情或判定。

### 四、HTML 视觉快照

适用条件：运行环境能打开本地或内存 HTML，并具备网页截图能力。

硬性要求：

1. HTML 必须自包含；不得依赖远程字体、远程图片、脚本、样式表或网络资源。
2. 使用语义化结构、CSS 变量和系统字体回退栈；至少支持中文衬线标题、中文正文和等宽数字。
3. 默认画布适配窄屏聊天栏；长主线、地点、身份和物品必须自动换行，不得横向溢出。
4. 生成后先检查文本完整性和可见范围，再截图为 PNG、JPEG 或 WebP。
5. 截图只包含面板本体，不包含浏览器工具栏、文件路径、调试信息或隐藏数据。
6. 视觉层级固定为：名字与身份 → 命运线 → 核心资源 → 状态与序列 → 随身与金钱。
7. 「主线」与「当下」通过文字层级、留白和旧金色横向细线建立联系；不得使用左侧竖条、竖向命运线或重复直立标记，其他装饰保持克制。
8. HTML 或截图失败时切换至 SVG 视觉快照；同一回合不得重复发送失败产物。
9. 以 360～430 CSS 像素宽的移动聊天栏为第一设计目标，建议使用 2 倍像素密度截图；正文在最终显示尺寸下不得小于约 14 CSS 像素。

### 五、SVG 视觉快照

适用条件：运行环境可以生成 XML 文本，并能显示 SVG 或将其光栅化。

硬性要求：

1. 使用固定 viewBox 和自适应宽高；不得依赖远程字体、远程图片、脚本或网络资源。
2. 所有文字先做 XML 转义；长字段按固定行宽换行或截断，不得溢出画布。
3. title、desc 或图片替代文本至少包含名字、地点、身体状态、精神状态、灵性、理智和污染。
4. 光栅化后检查尺寸、清晰度、完整边界和中文字体；失败时切换到平台富文本。
5. 同一 public_panel_model 的 HTML 与 SVG 版本必须字段一致，允许布局因平台宽度不同而变化。
6. 当前界面不能直接显示 SVG 时优先发送光栅图片；禁止把本地绝对路径当作用户可访问链接。
7. 默认使用接近 9:16 或 3:5 的竖向画布，按 2 倍移动端密度设计；面板必须能在手机中从上到下一次扫读，不得依赖放大查看核心数值。

### 六、平台富文本与极简文字

平台富文本使用短标题、粗体字段、分隔线和紧凑段落；移动端优先，不使用宽表格。

参考结构：

```markdown
状态 · [名字]

[身份] · [地点]

主线：[主线]
当下：[当下]

灵性 [当前]/[上限] · 理智 [当前]/100 · 污染 [当前]/100
身体 [身体] · 精神 [精神]
序列 [序列] · 途径 [途径] · 扮演度 [扮演度]

随身：[关键物品]
金钱：[金钱]
```

纯文字模式只在视觉快照和平台富文本均不可用或玩家明确指定时使用：

```text
状态
名字：xxx｜身份：xxx｜地点：xxx
主线：xxx
当下：xxx
灵性：72/100 ███████░░░
理智：100/100｜污染：0/100｜金钱：xxx
身体：健康｜精神：清醒
序列：凡人｜途径：未选择｜扮演度：不适用
随身：数枚便士、旧报纸
```

### 七、回合输出编排

每个游戏回合的核心信息必须先完成并发送，媒体生成不得阻塞裁决：

1. 时间戳与剧情推进。
2. 公开结算。
3. 按触发条件发送状态面板。
4. 一句轻提示。
5. 3～4 个选项与恒定自由行动。
6. 若属于关键场景且插图已开启，最后询问是否生成插图。

当前环境支持图片时，状态面板使用 PNG、JPEG 或 WebP；支持按钮时可以把建议选项映射为按钮。无论界面能力如何，自由行动始终允许玩家直接输入文字。输出失败后重发同一个已提交结果，不得重新裁决。

### 八、提示面板与主动轻提示

提示面板与状态面板使用同一公开模型，只包含角色当前有合理依据知道的方向：

- 眼下可做的事：2 条具体地点、动作或对象建议。
- 人物往来：最多 2 条近期人物或未处理事件。
- 命运线索：最多 2 条角色已经察觉的线索。

提示只提供方向，不泄露隐藏时钟、幕后身份、未发现危险或正典谜底。视觉快照沿用命运线设计；富文本与纯文字使用紧凑分组。

状态面板更新后，正文末尾可以附一句斜体轻提示；同一回合至多一次，不打断紧张剧情。重要剧情推进时，顺序固定为：先叙事宣告，再发送状态面板，最后附一句轻提示。

### 九、沉浸插图协议

插图用于关键人物设定、重要道具、场景建立与重大转折，不能替代核心叙事、判定或状态面板。

1. 角色创建完成且首次开局场景、面板与选项发送完毕后，询问一次：
   「是否开启沉浸插图？开启后，我会在关键场景核心信息输出完毕后询问是否生成。」
2. 默认不擅自生成。玩家选择开启后，关键场景先完整发送剧情、结算、面板和选项，再问：
   「要为这一幕生成一张插图吗？」
3. 玩家同意后才调用当前环境可用的高质量图像生成能力。提供商与模型由环境选择，不写死在规则中。
4. 生成请求不推进游戏时间、不消耗角色资源、不改变气运、不触发世界时钟，也不阻塞玩家继续行动。
5. 插图只使用角色已经知道或本轮正文已经公开的视觉事实；禁止通过背景人物、符号、物品、文字或构图泄露隐藏身份、幕后势力、未来事件或引擎真相。
6. 插图中的新增细节默认只是美术补充，不能自动成为可调查线索、正典事实、物品属性或 NPC 状态。只有正文明确确认后才能进入 journal.md。
7. 角色外貌、服装、标志物与重要道具建立 visual bible；后续提示词优先复用，以保持连续性。视觉档案只能保存公开事实。
8. 关键场景判定标准：角色定型、首次进入重要地点、首次见到关键 NPC 或道具、重大关系变化、序列晋升、命运锚点动摇、章节高潮与结局。
9. 普通移动、日常购物、重复战斗交换、规则问答、状态查询和失败重试不询问插图。
10. 图像生成失败、超时或平台无法发送时，只说明媒体未生成；游戏核心输出已经成立，继续接受玩家行动。

### 十、故障识别、调试与恢复

1. AI 无法直接读取玩家看到的最终结果时，不得宣称视觉呈现已经成功；只能说明产物已经生成或已发送。
2. 玩家反馈「图片打不开」「文字被裁切」「字体乱码」「按钮无效」时，视为有效故障证据，无需重复确认。
3. 调试顺序：公开模型字段 → HTML／SVG 生成 → 截图或光栅化 → 媒体上传 → 平台消息与按钮。
4. 调试、模式切换、截图和插图生成不推进剧情，不掷骰，不改变 campaign.turn、world_time、机会计数器、角色状态或世界时钟。
5. 文件账本可为界面设置增加 state_revision，并追加 interface_setting_changed 或 media_event；不得进入 journal.md 或 canon-deviations.md。
6. 恢复后从最近权威状态继续，不重掷、不重复结算。

### 十一、面板一致性与验收

1. 所有模式必须展示同一 state_revision 的 public_panel_model。
2. 每回合都从当前权威账本重建公开模型；灵性值、理智、污染、金钱及状态在对应变化后更新。面板与账本矛盾时，以最近一次有依据的结算为准并立即纠正。
3. 标签只显示当前状态；伙伴数值独立维护，禁止复制玩家数值。
4. 状态词只能从枚举表取值；随身物品只列关键项，最多 6 项。
5. 数值条为 20 格时，填充数 = round(当前值/上限×20)；0 全空，满值全满。
6. 同行为空时省略同行；物品为空时显示「数枚便士、一份旧报纸」。
7. 每种渲染器至少验证：中文、长地点、长主线、满灵性、零灵性、空物品、六件物品、无同行和有同行。
8. 连续切换模式后字段和值必须一致；任一模式失败后，下一模式必须继续展示同一 state_revision。
9. 图片面板必须验证清晰度、裁切、字体、替代文本和无隐藏信息泄露。
10. 实现保持两层边界：`public_panel_model` 只整理并校验公开字段；renderer 只接收该模型并输出视觉快照、平台富文本或纯文字。
11. 道具不存在全局通用的稀有度阶梯，渲染器不得根据名称或价格自行判级。公开模型可以为道具、效果和当前事件携带语义色与已确认的 `rank_label`；颜色只作辅助，名称、状态词和危险等级文字必须同时保留。
