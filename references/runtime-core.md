# 常规回合运行契约

> 配置：`turn-core-v1`
>
> 用途：为持续会话与无状态 IM 请求提供小型、可校验的每回合安全契约。它不取代 [ruleset.md](ruleset.md) 或任何权威规则模块。

每次游戏内裁决都要完整读取本文件。普通回合可以只携带本文件、当前权威状态的相关切片和最近事件；一旦命中后文的升级条件，必须在裁决前完整读取对应权威模块。规则不明确、相互冲突或当前上下文无法证明时，停止结算并升级读取，不得凭模型印象补规则。

## 一、可信加载与缓存

1. 从 [rules-manifest.json](rules-manifest.json) 读取 `runtime_loading.profile_id`、`turn_core_sha256` 与 `ruleset_digest`。宿主只能复用摘要完全匹配的缓存；任一文件变化、摘要缺失或校验失败都视为缓存未命中。
2. 本文件必须实际出现在当前模型上下文中。数据库里的“已加载”标记、旧会话记忆或摘要字符串本身不能替代规则文本。
3. 完整模块可以由持续会话上下文、不可变提示前缀或宿主内容缓存复用，但宿主必须保证模型可访问对应文本，并把已加载模块名与同一个 `ruleset_digest` 绑定。无法保证时按未加载处理。
4. 新建战役、显式迁移、故障恢复、规则摘要变化、状态版本异常或一致性失败时，完整读取 [ruleset.md](ruleset.md)、[core-rules.md](core-rules.md)、[adjudication-and-systems.md](adjudication-and-systems.md) 与 [causality-and-continuity.md](causality-and-continuity.md)。恢复完成后仍要按行动重新判断其他模块。
5. 常规回合不重复加载与当前裁决无关的完整历史或规则模块。缓存只减少输入，不放宽任何规则、校验、幂等或隐藏信息边界。

## 二、升级读取路由

遇到下列任一事项，先完整读取对应文件，再做决定：

- 创建角色、改变难度或节奏档、开场、自由度争议、内容边界、剧透范围、单主角控制、胜负或结局：读取 [core-rules.md](core-rules.md)。常规时间戳、选项和自由行动入口直接执行本契约。
- 骰点、属性、技能、风险、伤害、状态、灵性、理智、污染、失控、战斗、成长、经济、关系、组织权限、社会地位、承诺、世界时钟、线索、调查、章节或志向证据：读取 [adjudication-and-systems.md](adjudication-and-systems.md)。
- 命运锚点、因果值、重大正典事件偏移、跨场景隐藏世界变化、非标准状态补丁、恢复、迁移、总结、记忆锚或一致性争议：读取 [causality-and-continuity.md](causality-and-continuity.md)。普通单事件事务可直接执行本契约并交给确定性运行时校验。
- 精确人物、地点、组织、日期、正典冲突或来源置信度：读取 [canon-and-world.md](canon-and-world.md)。
- 途径、序列、能力、魔药、扮演、仪式、材料或封印物：读取 [pathways-and-powers.md](pathways-and-powers.md)。
- 面板触发、公开字段、命令、消息顺序、视觉回退或插图：读取 [presentation.md](presentation.md)。
- 多战役、数据库、并发、跨进程、无文件系统、导入导出或服务端恢复：读取 [runtime-and-storage.md](runtime-and-storage.md)。
- Telegram、Discord、Slack、按钮、消息拆分、重试、回调或媒体投递：读取 [transport-adapters.md](transport-adapters.md)。
- 状态卡截图、视觉连续性或图片生成：读取 [visual-media.md](visual-media.md)。

一次行动可以命中多个模块。任何不可逆后果、规则边界或数值公式只要没有在当前上下文中得到权威条款支持，就必须升级读取。纯投递重试、已提交结果的重发、状态查询和不推进世界时间的澄清不重新裁决。

## 三、最小回合上下文

宿主默认向裁决器提供下列工作集，而非整条事件链：

- `ruleset_version`、`ruleset_digest`、状态修订号、最后事件 ID、战役范围键与控制者。
- 当前世界时间、地点、难度、角色公开状态与裁决所需的隐藏状态。
- 当前章节、命运志向及其验收证据、活跃线索与调查路径、临近时钟、相关 NPC／组织／承诺／债务。
- 与本次行动直接相关的知识、正典记录、因果锚点、物品、能力与内容偏好。
- 最后 2～4 条事件，以及更早但仍构成前置条件的事件引用。

工作集必须带来源状态修订号；宿主应将其绑定到权威状态摘要或在事务内读取。字段缺失、投影过期、事件引用无法解析或行动触及未加载领域时，从权威状态补取相关切片。仍无法确认就读取完整状态并校验；禁止用剧情常识填空。

完整 `state.yaml` 或等价数据库记录仍是唯一当前状态，`events.jsonl` 或等价只追加日志仍是历史依据。精简上下文不是新的权威账本，也不得写回为完整状态。

## 四、每回合安全不变量

1. 先解析战役范围与控制者，再去重入口标识；重复 webhook、按钮或消息只能返回已保存结果。
2. 读取权威状态和最后事件，先恢复已追加但未提交的事件。若版本、修订或摘要不一致，停止本次新裁决。
3. 玩家可输入任何合理的世界内行动。推荐选项不能替玩家作决定，也不能强迫正典路线。
4. 角色知识与玩家知识分离。未发现的秘密、隐藏时钟、敌意、污染来源和未来事件不得进入公开叙事、面板或图片提示词。
5. 不滥用判定。只有结果存在真实不确定性且失败会改变局势时才掷骰；已掌握且无压力的行动直接成功。
6. 不可逆或显著风险行动先公开角色可预见的意图、方法、目标、公开修正、风险等级与后果类别，允许玩家在掷骰前调整。角色确实来不及反应时才可立即结算。
7. 随机结果必须来自 `scripts/roll_check.py`、已承诺 HMAC 流或可保存凭证的平台随机源。禁止在文字中挑选骰点、补掷或因表现失败重掷。
8. 失败必须改变局势、付出代价或打开替代入口。核心谜题至少保留两条独立调查路径，必要线索不能只被一次失败永久封死。
9. 好感、组织权限、社会地位、通缉热度、承诺、人情和财务债务分别记录。关系不能自动替代服从、授权或资源。
10. 命运志向的完成条件必须引用已经提交的事件证据。章节要有核心问题与压力源，并在至少一项不可逆变化发生后关闭。
11. 内容偏好与硬性避雷项持续有效。剧透设置只影响元讨论，不增加角色知识。
12. 时间戳、世界时钟、经济周期与事件后果只按可见因果推进，不能为了戏剧效果任意加速或制造惩罚。

## 五、事务与输出顺序

一次需要推进状态的行动遵循固定顺序：

1. 完成加载路由、范围解析、入口去重、状态读取与风险预告。
2. 必要时生成一次可审计随机结果。
3. 构造一个主事件，包含行动、风险、随机凭证、后果、带旧值检查的 `state_patch` 与公开结果。
4. 追加完整事件，再以预期修订号原子提交状态；更新公开日志并创建 outbox。
5. 提交成功后才发送带时间地点的剧情、公开结算、按时机出现的状态信息、轻提示、3～4 个建议选项与恒定自由行动入口。
6. 投递失败只重试 outbox。修复显示问题不能重写事件、推进时间或重新裁决。

若当前只是高风险行动的掷骰前确认，则只发送风险预告，不创建事件、不推进世界时间。若存储不可用，按权威降级协议生成完整且带摘要的私密记忆锚，并明确标记持久化降级。

## 六、媒体并行边界

确定性状态信息属于核心投递；若状态卡渲染或上传较慢，先发送同一状态修订的文字摘要，再异步补发图片。不得让玩家因等待视觉媒体而无法看到必要状态或继续选择。

AI 插图始终是可选、异步、非语义任务。核心剧情、结算与选择已经发送，且玩家对该场景明确同意后，才建立图片任务。图片任务只读取已公开事实和视觉连续性资料；成功、失败、超时或重试均不能改变事件、骰点、状态、资源或世界时间。

## 七、保守回退

出现以下任一情况时，不继续猜测：规则摘要不匹配、权威模块缺失、状态投影过期、并发修订冲突、重复入口归属不明、随机凭证无法保存、隐藏与公开边界不清、或旧战役尚未获准迁移。先补取权威资料、恢复或请求必要确认；已经提交的事实保持不变。
